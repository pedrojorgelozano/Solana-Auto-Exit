# Changelog

All notable changes to Auto-Exit are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Installers and checksums for each release are on the [Releases page](https://github.com/pedrojorgelozano/Solana-Auto-Exit/releases).

## [Unreleased]

Quality and robustness improvements after v0.3.1, driven by a real user hitting a broken-position-discovery bug, plus a small security-hardening pass. No breaking changes, no schema/migration changes, no new egress; one unused Tauri shell permission *removed*. Tests 154 → 169.

### Added
- **RPC / network mismatch warning on the dashboard.** Changing only the RPC URL in Settings doesn't change the active `network`, so pasting a devnet endpoint (or a provider that restricts `getProgramAccounts`) while the app is on mainnet made discovery query the wrong network and return "0 positions" with no error — the user thought they had nothing. `settings.get` now exposes `rpcNetworkMismatch` (computed via the existing `inferNetworkFromRpcUrl` host heuristic) and the dashboard surfaces a callout when the RPC host looks like a different network than the one selected. Unknown/private hosts return null → no nag for power users running their own node. See ADR-043.
- **Configurable receipt diff threshold.** The actual-vs-quoted difference on a close/swap receipt (`ActualLine`) was highlighted in warning above a hardcoded `0.01%`. Now a `/settings` field (`diffWarningThresholdBps`, persisted as `diff_warning_threshold_bps`) controls it; default 1 bps (= 0.01%, preserving prior behaviour), 0 flags any non-zero difference. Same pattern as the low-balance threshold; shown in % in the UI.
- **Token registry expanded (+10 verified mints).** Added PYUSD, JLP, jupSOL, INF, JTO, PYTH plus the top Solana stablecoins USDe, USDS, EURC, USDY — each mint *and* decimals verified one by one against CoinGecko/Solscan/Jupiter/DefiLlama. **USDe is 9 decimals** (not 6 like other stables); assuming 6 would have shown amounts off by 1000×. More pairs now render a symbol instead of a truncated address.

### Changed
- **Discovery errors for Meteora are now actionable.** `positions.listOwned` decorates errors that point at a restricted/disabled `getProgramAccounts` (the method Meteora discovery relies on, which some providers like QuickNode's standard plan cap) with a hint to switch to a provider that allows it. Confirmed in the wild: the reporting user sees all their pools after switching to Helius.
- **Settings/empty-state recommend a free Helius mainnet endpoint.** Strongly, with a signup link — without embedding an API key (the repo is public; a shared key would be scraped and rate-limited for everyone, and would break the "no egress by default" posture). See ADR-043.

### Security
- **SSRF defense extended to the position-discovery endpoints.** `assertSafeRpcUrl` (blocks cloud-metadata IPs, loopback, all-interfaces, non-http(s)/ws(s) schemes, embedded credentials) was applied on `tasks.create`, `settings.update` and `settings.testRpc`, but `positions.listOwned` / `positions.getSummary` passed the client-supplied `rpcUrl` straight to `adapter.setupRpc`. Since those two queries are read-only and reachable *without* unlocking the vault, they were the one remaining lever to make the server fetch an arbitrary host (e.g. `http://169.254.169.254/...`). Both now run the same guard as their first line and reject an unsafe URL with `BAD_REQUEST` before any connection is opened. New `positions.test.ts` covers it. The threat model is unchanged (single-user, localhost bind) — this closes an internal inconsistency rather than a remotely-reachable hole.
- **Removed the unused `shell:allow-execute` Tauri capability.** `packages/tauri/capabilities/default.json` granted the webview blanket command execution on top of the scoped `shell:allow-spawn` for the `auto-exit-server` sidecar. The frontend invokes no shell API, and the sidecar is spawned from Rust in `setup()` (which doesn't go through capabilities), so the permission was dead surface area — dropping it shrinks the blast radius of any future frontend compromise. No behavioural change.

### Docs
- **`.env.example` mainnet-gate comment corrected to opt-OUT.** The note next to `ALLOW_MAINNET_LIVE` still described the old opt-IN semantics ("you need `=true` for the bot to start"), contradicting the actual code (ADR-026: the gate is *open* by default; only `DRY_RUN=true` stops mainnet-live out of the box, and setting the var to `false` is the opt-out hardening for CI/unattended runs). Rewritten so a CLI user builds the correct mental model.

### Tests
- **154 → 169.** New `tokens.test.ts` (the first test in the `web` package, 8 tests) asserting token-registry invariants — unique mints/symbols, plausible base58 length (no `0OIl`), decimals 0-18, and the lookup helpers — so a duplicated or mistyped mint can't silently show the wrong symbol on a funded position. Plus a QuickNode endpoint-format case for `inferNetworkFromRpcUrl`, and `positions.test.ts` (6 tests) asserting the SSRF guard rejects metadata/loopback/all-interfaces URLs on both discovery endpoints.

## [0.3.1] — 2026-05-29

Patch release. Makes auto-update robust against the sidecar file-lock for clients upgrading from *any* prior version — including the v0.2.0 / v0.1.x builds that predate the Rust-side fix and therefore couldn't auto-update to v0.3.0 — by moving the kill into an NSIS preinstall hook that ships inside the installer itself. No other changes.

### Fixed
- **Sidecar-zombie fix, now also on the installer side (NSIS preinstall hook).** v0.3.0 fixed the auto-update file-lock from the *Rust* side (`on_download_finish` kills the sidecar before the installer runs), but that only helps when the build *performing* the update already carries it — so updating *from* v0.2.0 or earlier still aborted with *"Error opening file for writing"* (confirmed in the wild on the v0.2.0 → v0.3.0 hop). A new NSIS `NSIS_HOOK_PREINSTALL` (`packages/tauri/nsis-hooks.nsh`, wired via `bundle.windows.nsis.installerHooks`) runs `taskkill /F /T /IM auto-exit-server.exe` at the start of installation. Because it travels in the *new* installer, it protects the update regardless of which (possibly fix-less) version is being upgraded from — so v0.2.0 stragglers can finally auto-update to this release. Belt-and-suspenders with the Rust-side kill.

## [0.3.0] — 2026-05-29

The hardening release. Ships the P0 fix for the sidecar-zombie bug that broke auto-update. **Important:** the fix runs in the app *performing* the update (it kills the sidecar before the installer overwrites it), so it only takes effect for updates done *by* a build that already carries it — i.e. from v0.3.0 onward (v0.3.0 → v0.3.1+). Updating *to* v0.3.0 from v0.2.0 or earlier still hits the bug, because those builds predate the fix; install v0.3.0 manually instead (fully quit Auto-Exit first, then run the installer). Two safety/correctness fixes on top: resuming auto-exits after the wallet was locked now holds back any task whose price crossed its trigger while paused (instead of bulk-resuming it into an immediate close), and the "one active auto-exit per position" rule is now enforced on the backend, not just in the UI. Plus a large jump in automated test coverage (55 → 154) and some build hygiene. No breaking changes; no new permissions or egress.

### Tests
- **Test baseline grows 55 → 154.** A dedicated sprint added +75 (this bullet), closing priorities 1–3 of the standing test backlog (see `docs/TESTING.md`) with no production-code changes — only new `*.test.ts` files. The remaining +24 shipped alongside the resume-safety and one-auto-exit-per-position features (in the Changed section below).
  - **`wallet/vault.ts` (server)** — crypto roundtrip (create → unlock returns the same address and the same 64 bytes) and the B-09 error classification: `WrongPassphraseError` for a wrong passphrase and for tampered ciphertext (GCM auth fail), `VaultCorruptedError` for an altered address field, an unexpected payload length, or decrypted bytes that aren't a valid ed25519 keypair. The two latter branches need a vault whose GCM tag *validates* but whose content is wrong — impossible to reach by mangling a real vault — so the suite forges one with a local helper mirroring the vault format. Also: input validation (short passphrase, wrong-length / incoherent secret), `getRawSecret` returning an independent copy, and `lock`/`delete` clearing the in-memory key. Secrets are generated from `node:crypto` ed25519 (no `@solana/web3.js` dependency in the server).
  - **`engine/core/retry.ts`** — `isPermanentSolanaError` keyword heuristic (permanent vs transient, case-insensitive, non-`Error` inputs) and `withRetry` (success-first, retry-until-success, attempt exhaustion throws the last error, immediate rethrow when `retryableErrors` returns false, and a real-timer lower-bound check that the backoff is exponential rather than linear).
  - **`engine/core/loop.ts`** — tick `continue`/`stop` control flow and that a throwing tick is swallowed and the loop continues.
  - **`engine/config/env.ts`** — `loadBaseConfig` validation (required vars, network/direction/price/slippage/poll bounds), `parseBool` truthy/falsy keywords, and the mainnet gate (ADR-026).
  - **`tasks/manager.ts` lifecycle (server)** — `boot()` re-pauses active states (idle/armed/triggered/closing) with a `server-restart` history event and leaves terminal states untouched; `pauseAllOnVaultLock` pauses running tasks, aborts their controllers, and records `vault-locked`; B-04 atomicity (forcing `appendHistory` to throw rolls back `createTask`'s row insert); FK cascade of history on delete; `deleteAllTasks`; and cursor pagination + `historicalCounts`.

### Added
- **Health check for the SQLite file size.** New `meta` tRPC router with a `dbSize` query (a thin `statSync` over the DB path); the dashboard polls it every 5 min and shows an amber callout when the file grows past 50 MB. Normal usage is well under 2 MB/year, so the threshold is a sanity check against a future bug (e.g. an accidental `appendHistory` in the polling loop) — not a real disk-space concern. Callout has a CTA to `/tasks` so the user can review and clean up.
- **Server-side pagination on `/tasks` (history page).** Cursor-based on `createdAt`. New `tasks.listHistorical({ limit, cursor, filter })` returns up to 100 historical tasks per page with the filter applied server-side, plus `tasks.historicalCounts` for the tab counts. `/tasks/page.tsx` switched from `tasks.list` + client-side filtering to `useInfiniteQuery` with a "Load more" button. Power users with hundreds of historical tasks no longer pay the full-list render on every page load. The dashboard's "Recent activity" block still uses `tasks.list` (mixes live + historic, loads only the 8 most recent in normal use) — orthogonal and not a problem today.

### Changed
- **"One active auto-exit per position" is now enforced on the backend, not just the UI.** The rule (a position can have at most one non-terminal auto-exit at a time) was only enforced by the configure page, which shows an "existing watcher" panel instead of the form. A tRPC client bypassing the UI could create N watchers for the same position. `TaskManager.createTask` now checks for an occupying task (status `idle`/`armed`/`triggered`/`closing`/`paused` — terminal `done`/`error`/`stopped` don't occupy, mirroring the UI exactly) before inserting and throws a typed `DuplicateActiveTaskError`, which the `tasks.create` procedure maps to a `409 CONFLICT`. The check and insert are synchronous on a single-threaded server, so they're atomic — no race between two concurrent creates. The configure form already surfaces the message via `formatTrpcError` if the rare UI race hits it.
- **Safer "resume after unlock": tasks that crossed their trigger while locked are held back.** When the wallet is locked (manually or by a server restart) the watcher pauses active tasks; the dashboard then offered a single "Resume all" button. The footgun: if a position crossed its take-profit / stop-loss *while paused*, resuming it fired an immediate close (or a close after the buffer) — a close the user never chose, triggered by a market move behind their back. Now the dashboard asks the server (`tasks.resumeCandidates`) to read each paused task's current on-chain price (same path the watcher uses) and splits the callout in two: **"ready to resume"** (price hasn't crossed — bulk-resumes only these) and **"crossed their trigger — review first"** (a list with a per-task link to decide individually). The safety invariant: a task is only offered for bulk-resume if a real price was read *and* it hasn't crossed — anything unverified (RPC failed, position gone) falls into "review". The system-pause detection markers (previously duplicated as string literals in both `manager.ts` and the web client) are now centralized in `tasks/resume.ts` and imported where `lastError` is written, so the heuristic can't drift from its source.
- **Meteora `getPositionSummary` is O(1) instead of O(N).** The old path extracted the position owner from the account byte layout and then called `DLMM.getAllLbPairPositionsByUser(conn, owner)`, which iterates every DLMM position the owner has across all lb-pairs. For a wallet with N DLMM positions, every `/tasks/[id]` load did that walk. Replaced with `dlmm.getPosition(positionPk)` which decodes only the requested position; pair metadata (binStep, mints, decimals) comes from the `dlmm` instance directly.

### Fixed
- **QA audit hardening, round 2: 6 more fixes (B-08, B-09, B-11, B-14, B-15, B-17).** Closes out the original QA audit list. Mix of UX (B-08), correctness (B-09, B-11), and config consistency (B-14, B-15, B-17).
  - **B-08** — Lock button on `/wallet` disabled while a close is in flight. Locking during `closing` doesn't cancel the transaction (the signature is already at the RPC, we can't pull it from the mempool), but the UI used to let the user click and watch the watcher stop being able to record the receipt. Now derived from `tasks.list` (already cached for the dashboard), the button reads `"Closing in flight…"` with a tooltip explaining why.
  - **B-09** — `vault.unlock` errors are typed. `WrongPassphraseError` for GCM auth tag mismatch (by far the most common case); `VaultCorruptedError` for length mismatch, invalid ed25519 bytes, or address mismatch with the vault file. The unlock-limiter (5 fails / 5 min cool-down) now only counts `WrongPassphraseError` — before, a user receiving a corrupted vault would lock themselves out after 5 attempts with no path forward.
  - **B-11** — Meteora `closePosition` detects partial multi-tx failures. The SDK's `removeLiquidity` may emit N chained transactions when bins don't fit in one (CU limit). The old loop only tracked `lastSig`, so a failure on tx[N] after tx[0..N-1] succeeded left the position partially closed (some liquidity withdrawn, some fees claimed, PDA still open) while the receipt cheerfully said "Closed cleanly" with the last successful sig. Now: track `successfulSigs[]`, and if a later tx fails after earlier ones succeeded, throw an explicit error including which ones confirmed — the watcher surfaces it as `error` and the user sees the real state.
  - **B-14** — `runMigrations` throws when the migrations folder is missing, instead of `console.warn` + return false. The old behaviour let the server start and let drizzle blow up later with `"no such table: tasks"` on the first query, which was confusing. Now the error happens at boot with an actionable message.
  - **B-15** — `parseIntOr` clamps to a valid range. Previously, a negative `defaultSlippageBps` or `defaultPollMs` persisted in the DB (via manual migration or pre-zod-refinement) was passed through unchecked. Now out-of-range values fall back to the default.
  - **B-17** — `ALLOW_LOOPBACK_RPC` accepts the same truthy keywords as the engine's `parseBool` (`true`, `1`, `yes`, `on`, case-insensitive). Before, only the literal `"true"` worked, which surprised users coming from other projects' conventions. Unknown values still fail closed.
- **QA audit hardening: 5 correctness fixes from the standing backlog (B-04, B-05, B-07, B-10, B-20).** None visible to the user when everything goes well, but each one closes a real failure mode that was either silent or misleading.
  - **B-04** — `update tasks` + `appendHistory` no longer disjoint. The 9 call-sites in `TaskManager` that updated a task's status and recorded the corresponding history event ran as two independent writes; a server crash between them would leave history inconsistent with the status. All 9 pairs now run inside `db.transaction((tx) => …)` so either both writes commit or neither does.
  - **B-05** — `withRetry` no longer reruns permanent errors 5 times. `SlippageExceeded`, `InsufficientFunds`, "account not found" and friends are not transient; retrying just stacks latency before the user sees the actual error. New `retryableErrors` option on `RetryOptions` + exported `isPermanentSolanaError` helper (keyword-based heuristic over the error message — SDKs don't expose typed classes for these). Adopted in both the watcher loop and the legacy CLI runner.
  - **B-07** — `WalletVault.getRawSecret()` returns a copy. It used to hand out a reference to the internal `unlockedSecret` buffer; the Meteora adapter (the only caller today) could in principle mutate it, and worse, a concurrent `lock()` would `fill(0)` the same bytes the adapter was actively using. `return new Uint8Array(this.unlockedSecret)` decouples consumers from the vault's lifecycle.
  - **B-10** — `verifyTxBalances` now reads `meta.loadedAddresses`. The lookup was scanning only `message.accountKeys`; if the bot wallet was loaded via an Address Lookup Table (which is increasingly common in Solana programs), it never matched and `solDelta` came back as `0` — receipts silently said "0 SOL moved" when in fact SOL moved. New `allKeys(tx)` helper builds the global key list in the order Solana's pre/postBalances actually use: `[staticKeys, loadedWritable, loadedReadonly]`. Two new tests cover writable and readonly.
  - **B-20** — watcher crashes now mark the task as `error`. The `.catch` after spawning the watcher loop only logged; the task stayed in `armed` with `this.running.set(...)` already done, pretending to watch while the loop was dead. Now `markError(id, err)` runs in the catch so the task surfaces in the dashboard error callout and in `/tasks?filter=errors`.
- **Sidecar zombie blocking auto-update installer.** Verified end-to-end while shipping v0.2.0: the `tauri-plugin-updater` flow does check GitHub, shows the native dialog, downloads the new `.exe`, verifies the signature against the embedded pubkey, and launches the NSIS installer — but the Tauri shell exits through a path that bypasses the `RunEvent::Exit` handler where the sidecar is killed. Consequence: `auto-exit-server.exe` stays alive and holds an open handle on the file the installer is trying to overwrite, so NSIS aborts with *"Error opening file for writing"*. Any user with auto-update opt-in would hit this on the first real update. Fix: hook the `on_download_finish` callback of `download_and_install` to kill the sidecar after the download completes and before the installer launches — minimum window of "app without sidecar", and if the install fails the next launch respawns the sidecar normally.

## [0.2.0] — 2026-05-29

The "polished and honest" release. Major UI refresh (refined dark direction with sidebar nav and a visual hub on the dashboard), several real bugs fixed (the silent `0 SOL` callout, RPC/network coherence after switching, hydration mismatch that broke connect buttons after reload), and a sprint of post-release polish (test-RPC button, configurable low-balance threshold, legible zod errors, live wallet balance, three new UI primitives that distinguish buttons from links and internal from external navigation). Two operational notes for self-hosters: the auto-updater toggle now honestly says "manual update only" outside the Tauri desktop app, and `wallet.balance` rejects malformed addresses instead of letting the RPC return a cryptic error.

### Added
- **Three new UI primitives — `TextAction`, `DocsLink`, `ExternalLink`.** Before this, button-styled-as-text (Copy, Test connection, "use default"), internal docs links (`→ How encryption works`) and external links (GitHub INSTALL.md, Meteora, Helius) all shared the same `t-eyebrow muted + hover bright` styling. A user couldn't tell at a glance whether a string would do something local or take them away — and external links sometimes opened a new tab without any visual cue. The three primitives split the responsibility: `TextAction` carries a dotted underline (turns solid on hover) so it reads as "click but no navigation"; `DocsLink` adds an arrow `→` automatically (i18n strings no longer carry it) and stays muted; `ExternalLink` adds an `↗` icon, uses accent-bright, and sets `target="_blank" + rel="noopener noreferrer"` by default. ~20 call-sites migrated across `/settings`, `/wallet`, `/positions/[mint]`, `/tasks/[id]`, the connect-wallet modal, the home, and `/docs/operational`.
- **"Test connection" button on `/settings`.** Next to the RPC URL field — sends a `getVersion` JSON-RPC call to the URL currently in the input (not the persisted one, so you can test before saving) with a 5s timeout. Returns `OK · solana-core version · latency ms` in green on success, or a legible error in red. Passes through `assertSafeRpcUrl` first (same SSRF guard as the persist path) so it can't be used as a side-channel to probe internal IPs / cloud metadata endpoints. Fills the gap from the previous session's balance bug — a user configuring a new RPC had no way to confirm reachability before a watcher tried and failed.
- **Low-balance threshold configurable on `/settings`.** New `lowBalanceThresholdLamports` setting (default 50_000_000 = 0.05 SOL — covers ~10 closes + ATA creation, unchanged behaviour). Surfaced as a `SOL` input under a "Dashboard" panel; `0` disables the callout entirely. Previously hardcoded in `DashboardAlerts.tsx`. Useful for users who only operate stables (don't open new ATAs, can lower the threshold) or who close many tasks simultaneously (raise it).
- **Live balance on `/wallet`.** A new `Balance · X.XXXX SOL` row appears below the address when the wallet is unlocked, polling every 60 s. Previously the only place that showed live balance was the success screen of the post-Generate modal; opening `/wallet` to send funds from outside used to require checking Phantom / Solscan in another tab. Loading shows `…`, an RPC failure shows `—` (the explicit error callout already lives on the dashboard, the wallet page just doesn't lie about the number).
- **`UpdaterPanel` placeholder when running outside Tauri.** In the Docker / pnpm-from-source install paths the `tauri-plugin-updater` doesn't exist, so the auto-update toggle was a no-op that misled users into believing they had opted in. Detected via `window.__TAURI_INTERNALS__` post-hydrate; outside Tauri the panel now renders an honest copy *"Auto-update is only available in the installed desktop app… → How to update manually"* with a link to `INSTALL.md`. Inside Tauri the panel works as before.

### Fixed
- **`wallet.balance` now validates the address is a valid base58 Solana pubkey (B-18).** Input was `z.string().min(32)` — any 32+ char blob passed, and the RPC returned a confusing `Invalid param: WrongSize` that masked the real cause (a clipped paste, a stray space, a non-base58 character). New zod refine decodes via `getBase58Codec` and checks 32 bytes; failures produce an actionable message.
- **Zod validation errors from the backend now render as legible messages.** Catches in `/settings`, `/wallet`, `ConnectWalletModal`, and `/positions/[mint]/configure` used to display `err.message` directly — when the backend rejected an input with a `ZodError`, the message was the serialized JSON array of issues (`[{"code":"invalid_string","validation":"url","message":"Invalid url",...}]`). New helper `formatTrpcError` extracts the first `message` from `err.data.zodError` instead. Example seen in the wild: pasting `mi-rpc.foo` (no scheme) into the RPC URL used to show the JSON blob; now shows `"Invalid url"`.
- **`wallet.balance` no longer returns 0 silently on RPC failure.** Backend used `body.result?.value ?? 0` — any non-standard response shape (rate-limit HTML, JSON parse failure on weird responses) caused the function to return `lamports: 0` as if it were a successful query, triggering a false "low balance" callout on wallets that actually had SOL. Now throws a `TRPCError` if `body.result.value` is not a number, so the frontend can distinguish "the RPC didn't respond" from "the wallet has 0 SOL". A muted `v0.2.0-dev` (or whatever the workspace `package.json` currently declares) appears just below the wallet beacon. Read from `packages/web/package.json` via JSON import — when the next release bumps to `0.2.0` the badge updates automatically. Useful for bug reports, confirming an update was applied, and distinguishing pre-release from release. All workspace manifests (root, `web`, `server`, `tauri/package.json`, `tauri/tauri.conf.json`, `tauri/Cargo.toml`) bumped to `0.2.0-dev` to reflect that `main` is the pre-release path to v0.2.0.
- **New dashboard callout: "Couldn't check balance".** When the `wallet.balance` query fails (rate-limit on public RPC, misconfigured RPC URL, RPC down), the previous behaviour silently returned `0 lamports` and fired a false `BALANCE BAJO` callout. Now the backend throws explicitly when the RPC response is malformed; the frontend surfaces it as a dedicated amber callout with CTA to `/settings` so the user can fix the RPC URL.

### Fixed
- **`wallet.balance` no longer returns 0 silently on RPC failure.** Backend used `body.result?.value ?? 0` — any non-standard response shape (rate-limit HTML, JSON parse failure on weird responses) caused the function to return `lamports: 0` as if it were a successful query, triggering a false "low balance" callout on wallets that actually had SOL. Now throws a `TRPCError` if `body.result.value` is not a number, so the frontend can distinguish "the RPC didn't respond" from "the wallet has 0 SOL".
- **`rpcUrl` now coherent with `network` setting.** Two related bugs:
  - Fallback when no `rpc_url` is stored: `wallet.balance` had a hardcoded `DEFAULT_RPC_URL = devnet`, so a fresh-install wallet on mainnet would query devnet and report 0 SOL. Fixed to fall back to `DEFAULT_RPC_BY_NETWORK[network]` — same logic as `settings.get`.
  - Toggle network without touching rpcUrl: `settings.update` accepted independent changes, so a user that started on devnet and switched to mainnet would still have the devnet RPC stored. `wallet.balance` then queried devnet with a mainnet address → 0 SOL. Fix: when `network` changes, if the stored `rpcUrl` was one of the two canonical defaults (`api.mainnet-beta.solana.com` or `api.devnet.solana.com`), it auto-syncs to the canonical of the new network. Custom URLs (Helius, QuickNode, etc.) are preserved.
- **Copy: "In your range" → "In range"** (the existing `outOfRange` was already symmetric without "your").
- **`wallet.delete` now wipes the tasks table.** When you reset the wallet, the `.vault` file was being deleted but the tasks of the previous wallet stayed in the DB. The new wallet inherited them and the dashboard fired a bogus `N AUTO-EXITS PAUSED — Resume all` callout over tasks of an owner that no longer existed; clicking would fail at signing time with keys no longer in the vault. Backend now invokes `TaskManager.deleteAllTasks()` before `vault.delete()` — coherent with the 1 server = 1 wallet model. A `--wipe-all` flag on `scripts/seed-history.ts` helps anyone with already-orphaned tasks recover without resetting again.
- **Hydration mismatch in `LangProvider`.** `useState(detectInitial)` read `localStorage` in the state initializer; SSR has no localStorage so the server rendered with `en` while the client hydrated with `es` (or whatever was stored). React invalidated the entire tree on hydration, which silently broke every `onClick` handler attached to client components — explained why the connect-wallet buttons did nothing after a full reload. Fix: initial state is always `en` (matches SSR), a post-hydrate `useEffect` applies the real preference. ~16 ms flash for `es` users is the tradeoff.
- **Connect-wallet modal panel was invisible.** The original layout (`fixed inset-0 z-50 flex items-start justify-center` + `relative z-10 my-auto`) rendered the panel but it wasn't visually present in some viewports. Rewritten to a more bullet-proof centred layout: backdrop with `z-40` + panel with `fixed left-1/2 top-1/2 translate(-50%,-50%) z-50`. No flex tricks, no `my-auto`. Always visible.
- **`useSearchParams()` in `/tasks` blocked the production build.** Next 15 requires the hook inside a `<Suspense>` boundary. Wrapped `TasksListPage` accordingly so `pnpm build` passes.

### Changed
- **`BALANCE BAJO` callout shows the active network and hints at switching.** The previous body was `"Your bot has 0 SOL — may not afford fees when closing."` — context-free. If a user had SOL on mainnet but `/settings` was on devnet (a very common misconfiguration), the callout was technically truthful but caused real confusion. New body: `"Your bot has X SOL on devnet — may not afford fees when closing. If your wallet has SOL on mainnet, switch network in /settings."` Mainnet variant drops the conditional sentence.
- **CTA label of the low-balance callout: "Recargar" / "Top up" → "Ver wallet" / "Open wallet".** The tool does not top up balances — the SOL has to come from outside (Phantom transfer, exchange, faucet). The CTA links to `/wallet` where the user sees the address to receive funds. "Top up" implied a flow that doesn't exist.
- **`/tasks` reconverted into a pure history ledger.** The page used to mix live + paused + completed + errored tasks behind four filters; the live tabs duplicated the dashboard. Now only `COMPLETED` / `ERRORS` (default `COMPLETED`), title `History.`, description explicit: *"Closes and errors from past auto-exits. Live ones live in the dashboard."* The dashboard answers "what's happening now," `/tasks` answers "what happened" — one job per screen. Reads `?filter=errors` from the URL so the errored-tasks callout on the dashboard deep-links to the right tab.
- **`HistoryLedger` component shared between `/tasks` and the dashboard's "Recent activity" block.** One source of truth for the historical row format. Each row is a full-width Link (entire card clickable, animated chevron on the right, hover state on the whole row). Columns redesigned: dropped `Last price` and `Distance` (always empty on closed tasks — they read from `runtime.lastPrice` which is null when the watcher is gone), added `Closed by` (the trigger that fired, e.g. `TP · 195.00` in jade or `SL · 170.00` in amber — no more `≥`/`≤`/`@` jargon) and `Result` (real withdrawn amounts from `closeResult`, with swap output if present, or a truncated `lastError` for errored rows). Status pill enriched with solid background (jade for `done`, danger for `error`, neutral for `stopped`). Tabs reworked as real tabs: underline on the active one (GitHub/Tailwind-docs pattern), counts in parentheses (`COMPLETED (5)`).
- **Sidebar nav reordered to `Dashboard → History → Wallet → Settings`.** The `Auto-exits` item was renamed to `History` to match the page it actually opens (used to mislead users into thinking they'd see live ones). Wallet button at the foot wears a `border-y` so it reads as a control, not a row of info.
- **Back link on `/tasks/[id]` is now dynamic.** Live tasks (`idle/armed/triggered/closing/paused`) → `← Dashboard` (where the task lives). Historical tasks (`done/stopped/error`) → `← History`. Predictable, doesn't depend on browser history, works on deep links.
- **`/wallet` rewritten to drop jargon.** The page title was `The keypair that signs your closes.` — three layered crypto-isms that meant nothing to a casual user. Now: `Your bot's wallet.` with description *"The account the bot uses to open and close your auto-exits. It lives encrypted on your machine and only unlocks when you unlock it."* The technical detail (scrypt + AES-256-GCM) stays alive in the `→ How encryption and key storage work` link right below.
- **Address shown as truncated by default with copy + Solscan + expand.** The full wallet address (44 chars of mono) used to fill almost a line. Public information, yes, but no real use case demands seeing it always. New `AddressDisplay` component: `7ud2i3rg…WzYobC` by default, button `Copy` with feedback, toggle `Show full` for users who want it, link `View on Solscan` with the right cluster. Phantom / Backpack / Solscan all do this.
- **`SIM` badge became `Simulated`, lives outside the status pill, has a tooltip.** The old `COMPLETED · SIM` broke into two lines because it didn't fit in a rounded pill. New `SimTag` component renders amber and adjacent, with `title=` explaining *"This auto-exit ran in simulation mode: no real on-chain transactions were executed."*
- **Three new contextual deep-links to history.** The dashboard's `History →` section header link was removed (third link to the same screen — the sidebar and the bottom block already cover it). The errored-tasks callout's CTA is now `View in history` (was `View tasks`) and points at `/tasks?filter=errors`. The `task → auto-exit` rename completed for the five remaining strings in docs/settings copy (internal variable names like `tasksList`, `taskDetail`, `perTaskNote` stay).
- **Dashboard rewritten as a visual hub.** The home `/` is no longer a column-tabular list with `Status / Position / Auto-exit / Action` headers. Each position renders as a row with a header (pair + protocol pill + in/out range pill + a richer status pill on the right), a big mono price (with the quote symbol next to it), a `TriggerBand` (horizontal track with the live price node positioned between SL on the left and TP on the right; jade fragment up to the node when watching, grey when paused), and a 3-column TP/SL/Nearest stack (mono, jade/amber/contextual colour). Rows whose watcher is `armed/triggered/closing` render as elevated cards with a jade left stripe; rows that are paused or have no auto-exit render as flat lines with a subtle hairline. Section header `Now watching · NN — Each row closes itself the moment price crosses a target` + `Open the ledger →` link added above the list. The `StatStrip` (3 KPI columns above the hub: Watching count, Nearest trigger global, Last update) was removed — when there's one task it duplicates the per-row Nearest, and when there are N it hides per-row info, so it gave less than it took.
- **Contextual dashboard alerts replace the StatStrip.** Three amber callouts now appear above the hub only when they apply (zero in the 95 % case when everything is fine): `BALANCE BAJO` if the bot wallet has less than 0.05 SOL (may not afford fees when closing), `N AUTO-EXITS EN ERROR` linking to the ledger, and the new bulk-resume callout below. The previous wallet-locked banner became its own dedicated callout (`LockedCallout`) with eyebrow + body + CTA `Desbloquear`, instead of the easy-to-miss inline span that lived inside the page header.
- **Bulk-resume after unlocking.** When you unlock the wallet, instead of having to open each auto-exit and click Resume one by one, the dashboard now shows a callout `N AUTO-EXITS PAUSADOS AL BLOQUEAR LA WALLET — Resume all` that re-arms every task that was auto-paused by the system (vault-lock or server-restart, detected via `lastError` string match). User-paused tasks are not included — those are intentional and need an explicit individual resume. Snapshot-check ("which of these crossed a trigger during lockdown, surface them separately") is on the backlog for a later iteration.
- **Live time-buffer countdown on the dashboard.** When a trigger has been crossed and the task is waiting out its anti-flapping buffer before closing, the row shows `BUFFER · 5m 12s LEFT` in pulsing amber, refreshed every second. Visible only while the countdown is running — invisible the rest of the time. Faithful to the "set and forget" promise: nothing screams unless there's a decision to make.
- **Sidebar brand mark.** The sidebar logo is now a monogram `A` in mono jade inside the same accent-dim chip. Previous icon (door + arrow) was the universal "logout" glyph and users were reading it as a sign-out button instead of the product logo.
- **Token logos hidden behind a kill-switch.** The previous coloured circles with letter initials (placeholder `TokenBadge`) looked like generic AI mock-up and have been hidden globally via `HIDE_BADGES = true`. The component stays in tree; once real SVG logos are bundled (item on the redesign backlog) flip the flag and reactivate.

Affected: dashboard locked-callout, paused-after-lock activity events (`pausedVaultLocked`, `pausedServerRestart`), and the `/wallet` security paragraph.

The global header has been replaced by a left sidebar with brand + nav + server/wallet beacons. Below the hero: trigger cards in a 2-column grid (with distance bar and buffer footer), a position-holdings panel with a 2×2 grid (liquidity, pending fees, range status, estimated value computed in the quote token without an external oracle), a right-side sticky aside with Details (protocol / network / exit token / buffers / slippage / position mint), and a full-width Activity timeline with coloured nodes. Layout is `1fr 332px` on `lg+`, stacks on mobile.
- **Pages anchored to the sidebar.** All page roots (`/`, `/wallet`, `/tasks`, `/tasks/[id]`, `/positions/[mint]`, `/settings`, `/docs/*`, `error`, `not-found`) switched from `mx-auto` to `mr-auto`. On wide viewports the content used to centre inside the column-after-sidebar leaving a ~250 px hole between the sidebar and the content; now it hugs the sidebar with the overflow on the right, which feels more natural.
- **Typography scaled up for readability.** Body 15→17 px, eyebrows 11→13 px, t-h2 17→19 px, t-h3 15→17 px, t-h1 28-36→32-40 px. Inline small sizes across all components bumped one step up (`text-[10-12.5px]` → `text-[12-14px]`). Big numbers in the hero stay large (28–54 px). Targets older users who reported the previous scale as too small.
- **Number formatting: 2 decimals + English thousands separator.** Prices and triggers now show `22.38` instead of `22.3773` by default, with auto-bump to 4–8 decimals for very small numbers (BONK-style memes) so precision is not lost. Amounts ≥ 1,000 use the English thousands separator (`1,234.56`). Pool-range rates show as plain numbers (no currency suffix) following the Orca/Meteora convention; the hero anchors the denomination once with `1 SOL = X devUSDC`. Token amounts (liquidity, fees, estimated value) keep their symbol because they are actual amounts, not rates.
- **Lock-wallet moved out of the sidebar.** The button used to live at the foot of the sidebar where it invited a user to press it by default, but locking pauses every active auto-exit — which breaks the "set and forget" promise. Lock now lives only inside `/wallet` as a panel with explicit copy on what locking actually does, and a link to `/docs/security#hot-wallet-tradeoff` for the trade-off. The new section in `/docs/security` documents the hot-wallet posture honestly: the bot needs the key decrypted in RAM while operating, which is the same model Phantom and Backpack use while unlocked; the real mitigation is operational — *treat the bot wallet as a hot operational account, never your cold holdings*. See [ADR-039](docs/DECISIONS.md).

## [0.1.1] — 2026-05-27

Maintenance release. The Windows installer picks up two wallet-import UX fixes; the rest are infrastructure improvements (Docker self-hosted stack + hardening + multi-platform install docs) that don't change the installer behavior.

### Added
- **Self-hosted Docker stack** — `docker compose up` now serves both the server (:7777) and the web UI (:3000) from a single image. Both bind to `127.0.0.1`. Open `http://127.0.0.1:3000` in your browser. Targets Linux/Mac users who don't have a native installer yet; also works on Windows. See [ADR-036](docs/DECISIONS.md).
- **Run from source with pnpm** — a third install path (any OS) documented in [INSTALL.md](docs/INSTALL.md), intended for hardened hosts where Docker's container network clashes with strict firewall / kill-switch VPN rules, and for development.
- **Multi-platform install guide** — [INSTALL.md](docs/INSTALL.md) now covers Windows (native installer + Docker), macOS (Docker + source), and Linux (Docker + source), with prerequisites step-by-step, troubleshooting (Docker group + logout, DNS issues including hardened-network workarounds, pnpm not found), privacy notes for Docker Desktop telemetry.

### Security
- **Docker stack hardened** — six standard controls applied to both containers: non-root user (uid 1000), read-only root filesystem (with tmpfs for `/tmp`, `/home/node` and Next.js cache), all Linux capabilities dropped, `no-new-privileges`, memory/CPU limits, and HTTP healthchecks (web waits for the server to be healthy before starting). On Linux with a non-1000 host user, `./packages/server/data/` needs `chown -R 1000:1000` once; Docker Desktop on Windows/Mac handles it transparently. See [ADR-037](docs/DECISIONS.md).

### Changed
- **Wallet import errors are now actionable and non-leaking.** A bad keypair (Solana error #3704004, `PUBLIC_KEY_MUST_MATCH_PRIVATE_KEY`) and non-base58 characters in the input (#8078012) used to surface as cryptic `Solana error #XXXXXXX; decode this error...` messages — and the latter leaked the offending value into the message. Now: the keypair error becomes a clear "the private key bytes do not form a valid keypair"; the base58 error names the offending characters with their Unicode code point and detects homoglyphs (Cyrillic letters that look identical to Latin ones — caused by browser auto-translation overwriting the DOM text). _This change is in the installer._

## [0.1.0] — 2026-05-22

First public release — a self-hosted desktop app that watches Orca and Meteora liquidity positions on Solana and closes them when price hits a take-profit or stop-loss.

### Added
- Take-profit and stop-loss auto-exits for **Orca Whirlpools** and **Meteora DLMM** positions, with optional swap-to-exit into a token of your choice.
- **Windows desktop app** — bundles the UI and a local server sidecar; no Node.js or terminal required.
- **Encrypted wallet vault** — `scrypt` + AES-256-GCM, per-account private keys only (never seed phrases).
- **Test (devnet) / real (mainnet)** network toggle, with a two-step confirmation before switching to real funds.
- Editorial UI with in-app documentation, in English and Spanish.
- **Opt-in auto-update** via GitHub Releases — off by default.
- `SHA256SUMS.txt` published with each release for download integrity verification.
