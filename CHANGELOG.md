# Changelog

All notable changes to Auto-Exit are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Installers and checksums for each release are on the [Releases page](https://github.com/pedrojorgelozano/Solana-Auto-Exit/releases).

## [Unreleased]

### Fixed
- **`wallet.delete` now wipes the tasks table.** When you reset the wallet, the `.vault` file was being deleted but the tasks of the previous wallet stayed in the DB. The new wallet inherited them and the dashboard fired a bogus `N AUTO-EXITS PAUSED — Resume all` callout over tasks of an owner that no longer existed; clicking would fail at signing time with keys no longer in the vault. Backend now invokes `TaskManager.deleteAllTasks()` before `vault.delete()` — coherent with the 1 server = 1 wallet model. A `--wipe-all` flag on `scripts/seed-history.ts` helps anyone with already-orphaned tasks recover without resetting again.
- **Hydration mismatch in `LangProvider`.** `useState(detectInitial)` read `localStorage` in the state initializer; SSR has no localStorage so the server rendered with `en` while the client hydrated with `es` (or whatever was stored). React invalidated the entire tree on hydration, which silently broke every `onClick` handler attached to client components — explained why the connect-wallet buttons did nothing after a full reload. Fix: initial state is always `en` (matches SSR), a post-hydrate `useEffect` applies the real preference. ~16 ms flash for `es` users is the tradeoff.
- **Connect-wallet modal panel was invisible.** The original layout (`fixed inset-0 z-50 flex items-start justify-center` + `relative z-10 my-auto`) rendered the panel but it wasn't visually present in some viewports. Rewritten to a more bullet-proof centred layout: backdrop with `z-40` + panel with `fixed left-1/2 top-1/2 translate(-50%,-50%) z-50`. No flex tricks, no `my-auto`. Always visible.
- **`useSearchParams()` in `/tasks` blocked the production build.** Next 15 requires the hook inside a `<Suspense>` boundary. Wrapped `TasksListPage` accordingly so `pnpm build` passes.

### Changed
- **`/tasks` reconverted into a pure history ledger.** The page used to mix live + paused + completed + errored tasks behind four filters; the live tabs duplicated the dashboard. Now only `COMPLETED` / `ERRORS` (default `COMPLETED`), title `History.`, description explicit: *"Closes and errors from past auto-exits. Live ones live in the dashboard."* The dashboard answers "what's happening now," `/tasks` answers "what happened" — one job per screen. Reads `?filter=errors` from the URL so the errored-tasks callout on the dashboard deep-links to the right tab.
- **`HistoryLedger` component shared between `/tasks` and the dashboard's "Recent activity" block.** One source of truth for the historical row format. Each row is a full-width Link (entire card clickable, animated chevron on the right, hover state on the whole row). Columns redesigned: dropped `Last price` and `Distance` (always empty on closed tasks — they read from `runtime.lastPrice` which is null when the watcher is gone), added `Closed by` (the trigger that fired, e.g. `TP · 195.00` in jade or `SL · 170.00` in amber — no more `≥`/`≤`/`@` jargon) and `Result` (real withdrawn amounts from `closeResult`, with swap output if present, or a truncated `lastError` for errored rows). Status pill enriched with solid background (jade for `done`, danger for `error`, neutral for `stopped`). Tabs reworked as real tabs: underline on the active one (GitHub/Tailwind-docs pattern), counts in parentheses (`COMPLETED (5)`).
- **Sidebar nav reordered to `Dashboard → History → Wallet → Settings`.** The `Auto-exits` item was renamed to `History` to match the page it actually opens (used to mislead users into thinking they'd see live ones). Wallet button at the foot wears a `border-y` so it reads as a control, not a row of info.
- **Back link on `/tasks/[id]` is now dynamic.** Live tasks (`idle/armed/triggered/closing/paused`) → `← Dashboard` (where the task lives). Historical tasks (`done/stopped/error`) → `← History`. Predictable, doesn't depend on browser history, works on deep links.
- **`/wallet` rewritten to drop jargon.** The page title was `The keypair that signs your closes.` — three layered crypto-isms that meant nothing to a casual user. Now: `Your bot's wallet.` with description *"The account the bot uses to open and close your auto-exits. It lives encrypted on your machine and only unlocks when you unlock it."* The technical detail (scrypt + AES-256-GCM) stays alive in the `→ How encryption and key storage work` link right below.
- **Address shown as truncated by default with copy + Solscan + expand.** The full wallet address (44 chars of mono) used to fill almost a line. Public information, yes, but no real use case demands seeing it always. New `AddressDisplay` component: `7ud2i3rg…WzYobC` by default, button `Copy` with feedback, toggle `Show full` for users who want it, link `View on Solscan` with the right cluster. Phantom / Backpack / Solscan all do this.
- **`SIM` badge became `Simulated`, lives outside the status pill, has a tooltip.** The old `COMPLETED · SIM` broke into two lines because it didn't fit in a rounded pill. New `SimTag` component renders amber and adjacent, with `title=` explaining *"This auto-exit ran in simulation mode: no real on-chain transactions were executed."*
- **Three new contextual deep-links to history.** The dashboard's `History →` section header link was removed (third link to the same screen — the sidebar and the bottom block already cover it). The errored-tasks callout's CTA is now `View in history` (was `View tasks`) and points at `/tasks?filter=errors`. The `task → auto-exit` rename completed for the five remaining strings in docs/settings copy (internal variable names like `tasksList`, `taskDetail`, `perTaskNote` stay).
- **Dashboard rewritten as a visual hub.** The home `/` is no longer a column-tabular list with `Status / Position / Auto-exit / Action` headers. Each position renders as a row with a header (pair + protocol pill + in/out range pill + a richer status pill on the right), a big mono price (with the quote symbol next to it), a `TriggerBand` (horizontal track with the live price node positioned between SL on the left and TP on the right; jade fragment up to the node when watching, grey when paused), and a 3-column TP/SL/Nearest stack (mono, jade/amber/contextual colour). Rows whose watcher is `armed/triggered/closing` render as elevated cards with a jade left stripe; rows that are paused or have no auto-exit render as flat lines with a subtle hairline. Section header `Now watching · NN — Each row closes itself the moment price crosses a target` + `Open the ledger →` link added above the list. The `StatStrip` (3 KPI columns above the hub: Watching count, Nearest trigger global, Last update) was removed — when there's one task it duplicates the per-row Nearest, and when there are N it hides per-row info, so it gave less than it took.
- **Contextual dashboard alerts replace the StatStrip.** Three amber callouts now appear above the hub only when they apply (zero in the 95 % case when everything is fine): `BALANCE BAJO` if the bot wallet has less than 0.05 SOL (may not afford fees when closing), `N AUTO-EXITS EN ERROR` linking to the ledger, and the new bulk-resume callout below. The previous wallet-locked banner became its own dedicated callout (`LockedCallout`) with eyebrow + body + CTA `Desbloquear`, instead of the easy-to-miss inline span that lived inside the page header.
- **Bulk-resume after unlocking.** When you unlock the wallet, instead of having to open each auto-exit and click Resume one by one, the dashboard now shows a callout `N AUTO-EXITS PAUSADOS AL BLOQUEAR LA WALLET — Resume all` that re-arms every task that was auto-paused by the system (vault-lock or server-restart, detected via `lastError` string match). User-paused tasks are not included — those are intentional and need an explicit individual resume. Snapshot-check ("which of these crossed a trigger during lockdown, surface them separately") is on the backlog for a later iteration.
- **Live time-buffer countdown on the dashboard.** When a trigger has been crossed and the task is waiting out its anti-flapping buffer before closing, the row shows `BUFFER · 5m 12s LEFT` in pulsing amber, refreshed every second. Visible only while the countdown is running — invisible the rest of the time. Faithful to the "set and forget" promise: nothing screams unless there's a decision to make.
- **Sidebar brand mark.** The sidebar logo is now a monogram `A` in mono jade inside the same accent-dim chip. Previous icon (door + arrow) was the universal "logout" glyph and users were reading it as a sign-out button instead of the product logo.
- **Token logos hidden behind a kill-switch.** The previous coloured circles with letter initials (placeholder `TokenBadge`) looked like generic AI mock-up and have been hidden globally via `HIDE_BADGES = true`. The component stays in tree; once real SVG logos are bundled (item on the redesign backlog) flip the flag and reactivate.
- **`vault` is no longer used in user-facing copy.** Strings exposed in the UI now say `wallet` everywhere — the `.vault` file on disk is an internal name. Affected: dashboard locked-callout, paused-after-lock activity events (`pausedVaultLocked`, `pausedServerRestart`), and the `/wallet` security paragraph.
- **Refreshed UI direction — "refined minimal dark"** (in branch, not yet merged to `main`). The whole visual layer has been redone: dark `#0b0d0f` surface with jade accent, Hanken Grotesk sans for body and headings (Newsreader italic for accents), Spline Sans Mono for numbers. The global header has been replaced by a left sidebar with brand + nav + server/wallet beacons. Dashboard, ledger and settings have been re-laid out per the new direction. **No functionality added or removed** — every flow you can do today still works the same. See [ADR-038](docs/DECISIONS.md), supersedes [ADR-017](docs/DECISIONS.md).
- **Auto-exit detail screen redesigned.** `/tasks/[id]` follows the new `auto-exit-detail.html` mockup: header with token-pair badges + protocol pill + status pill, hero panel with the live price (big mono) plus a **new visual price band** that draws the liquidity range as a jade-tinted zone with explicit min/max labels, stop-loss and take-profit flags below, and the live price as a glowing node. Below the hero: trigger cards in a 2-column grid (with distance bar and buffer footer), a position-holdings panel with a 2×2 grid (liquidity, pending fees, range status, estimated value computed in the quote token without an external oracle), a right-side sticky aside with Details (protocol / network / exit token / buffers / slippage / position mint), and a full-width Activity timeline with coloured nodes. Layout is `1fr 332px` on `lg+`, stacks on mobile.
- **Pages anchored to the sidebar.** All page roots (`/`, `/wallet`, `/tasks`, `/tasks/[id]`, `/positions/[mint]`, `/settings`, `/docs/*`, `error`, `not-found`) switched from `mx-auto` to `mr-auto`. On wide viewports the content used to centre inside the column-after-sidebar leaving a ~250 px hole between the sidebar and the content; now it hugs the sidebar with the overflow on the right, which feels more natural.
- **Typography scaled up for readability.** Body 15→17 px, eyebrows 11→13 px, t-h2 17→19 px, t-h3 15→17 px, t-h1 28-36→32-40 px. Inline small sizes across all components bumped one step up (`text-[10-12.5px]` → `text-[12-14px]`). Big numbers in the hero stay large (28–54 px). Targets older users who reported the previous scale as too small.
- **Number formatting: 2 decimals + English thousands separator.** Prices and triggers now show `22.38` instead of `22.3773` by default, with auto-bump to 4–8 decimals for very small numbers (BONK-style memes) so precision is not lost. Amounts ≥ 1,000 use the English thousands separator (`1,234.56`). Pool-range rates show as plain numbers (no currency suffix) following the Orca/Meteora convention; the hero anchors the denomination once with `1 SOL = X devUSDC`. Token amounts (liquidity, fees, estimated value) keep their symbol because they are actual amounts, not rates.
- **Lock-wallet moved out of the sidebar.** The button used to live at the foot of the sidebar where it invited a user to press it by default, but locking pauses every active auto-exit — which breaks the "set and forget" promise. Lock now lives only inside `/wallet` as a panel with explicit copy on what locking actually does, and a link to `/docs/security#hot-wallet-tradeoff` for the trade-off. The new section in `/docs/security` documents the hot-wallet posture honestly: the bot needs the key decrypted in RAM while operating, which is the same model Phantom and Backpack use while unlocked; the real mitigation is operational — *treat the bot wallet as a hot operational account, never your cold holdings*. See [ADR-039](docs/DECISIONS.md).

## [0.1.1] — 2026-05-27

Maintenance release. The Windows installer picks up two wallet-import UX fixes; the rest are infrastructure improvements (Docker self-hosted stack + hardening + multi-platform install docs) that don't change the installer behavior.

### Added
- **Self-hosted Docker stack** — `docker compose up` now serves both the server (:7777) and the web UI (:3000) from a single image. Both bind to `127.0.0.1`. Open `http://127.0.0.1:3000` in your browser. Targets Linux/Mac users who don't have a native installer yet; also works on Windows. See [ADR-036](docs/DECISIONS.md).
- **Run from source with pnpm** — a third install path (any OS) documented in [INSTALL.md](docs/INSTALL.md), intended for hardened hosts where Docker's container network clashes with strict firewall / kill-switch VPN rules, and for development.
- **Multi-platform install guide** — [INSTALL.md](docs/INSTALL.md) now covers Windows (native installer + Docker), macOS (Docker + source), and Linux (Docker + source), with prerequisites step-by-step, troubleshooting (Docker group + logout, DNS issues including hardened-network workarounds, pnpm not found), privacy notes for Docker Desktop telemetry.

### Security
- **Docker stack hardened** — six standard controls applied to both containers: non-root user (uid 1000), read-only root filesystem (with tmpfs for `/tmp`, `/home/node` and Next.js cache), all Linux capabilities dropped, `no-new-privileges`, memory/CPU limits, and HTTP healthchecks (web waits for the server to be healthy before starting). On Linux with a non-1000 host user, `./packages/server/data/` needs `chown -R 1000:1000` once; Docker Desktop on Windows/Mac handles it transparently. See [ADR-037](docs/DECISIONS.md).

### Changed
- **Wallet import errors are now actionable and non-leaking.** A bad keypair (Solana error #3704004, `PUBLIC_KEY_MUST_MATCH_PRIVATE_KEY`) and non-base58 characters in the input (#8078012) used to surface as cryptic `Solana error #XXXXXXX; decode this error...` messages — and the latter leaked the offending value into the message. Now: the keypair error becomes a clear "the private key bytes do not form a valid keypair"; the base58 error names the offending characters with their Unicode code point and detects homoglyphs (Cyrillic letters that look identical to Latin ones — caused by browser auto-translation overwriting the DOM text). _This change is in the installer._

## [0.1.0] — 2026-05-22

First public release — a self-hosted desktop app that watches Orca and Meteora liquidity positions on Solana and closes them when price hits a take-profit or stop-loss.

### Added
- Take-profit and stop-loss auto-exits for **Orca Whirlpools** and **Meteora DLMM** positions, with optional swap-to-exit into a token of your choice.
- **Windows desktop app** — bundles the UI and a local server sidecar; no Node.js or terminal required.
- **Encrypted wallet vault** — `scrypt` + AES-256-GCM, per-account private keys only (never seed phrases).
- **Test (devnet) / real (mainnet)** network toggle, with a two-step confirmation before switching to real funds.
- Editorial UI with in-app documentation, in English and Spanish.
- **Opt-in auto-update** via GitHub Releases — off by default.
- `SHA256SUMS.txt` published with each release for download integrity verification.
